# Class 171 live-start header check-byte correction

The previous `FE - selected CCF[0x0231]` calculation reproduced the original captured identity but did not preserve the observed header balance when identity and wheel data changed. A manual CCF change to `A9` also failed on the recorder: the old generator turned that byte into `55`. Changing the file alone was not a validated repair.

The generator now calculates the outgoing check byte from the **validated current-recorder data** and the target wire mode:

```text
wire check = (RX page 1 payload[0x86] + RX page 1 payload[0xB8]
              - target wire mode - 0x07) modulo 256
```

`07` is the empirical structural delta for this captured Class 171 header transformation. This is not a checksum specification for other recorder formats. The transport check remains the sum of the actual outgoing payload modulo 256; it is never forced to a constant.

Both the single-page helper and complete START/restoration generator share this calculation. CCF `0x0231` is no longer used to generate the outgoing check byte. The target mode still comes from the selected CCF for START and from the frozen recorder snapshot for restoration.

For the changed header represented by the regression, the generated START check is `9F` and restoration check is `A2`. All three authoritative legacy START/STOP exchanges remain byte-for-byte identical. Regression data uses the public golden fixtures and generated byte deltas; private uploaded captures and CCFs are not committed.

Unexpected replies still stop the state machine before later commands. The error now reports complete expected/received frames, their lengths and the first mismatch. A captured `15` reply is not accepted as `06`.

Software validation covers unchanged golden exchanges, edited headers, mode changes, input immutability, checksum provenance, invalid recorder checks and rejection without final live-start transmission. The Linux portable run has one unchanged Windows-path assertion; the complete supported suite runs on Windows.

**Recorder acceptance of the new generated header still requires a hardware test.** Do not treat the failed A9 file patch or passing software replays as a successful hardware result.
