# Class 171 controlled bench live integration

## Status

The fully generated START exchange is connected to the Class 171 live service
for controlled bench validation. This is software validation only; no claim of
successful OTMR hardware operation is made.

## START preflight

Before generated write 1/7 can be transmitted, the service requires and checks:

1. an explicitly selected `CcfDocument` and an immutable snapshot of its current
   working bytes;
2. zero error-severity results from the existing `CcfValidator` checks;
3. a Class 171 vehicle-type header;
4. byte-compatible firmware/serial/vehicle/unit/type identity data between the
   selected CCF and recorder RX page `01 02`;
5. complete, checksum-valid recorder pages `01 02`, `01 04`, `01 06`, `01 08`,
   `01 0A`, and `01 0C`;
6. successful in-memory generation of all seven START writes and all seven
   restoration writes from a deep-copied recorder snapshot;
7. exact write count, page order, frame and payload lengths, framing, calculated
   modulo-256 checks, and one known provenance entry for every generated byte.

Any failure leaves the service in `RecorderConfigurationWriteBlocked`, reports
the specific failing condition, sends no generated configuration write, and
never enters `LiveActive`.

## Integrated START ordering

The existing reply-gated interrogation runs through complete transactions
`01 01` to `01 0C`. Preflight then completes before these generated writes:

| Write | Captured operation | Next required reply |
|---:|---|---|
| 1/7 | `000301`, `01 0C` acknowledgement | none between writes 1 and 2 in HHD |
| 2/7 | `000312`, page 1 | exact complete `01 0D` |
| 3/7 | `000335`, page 2 | exact complete `01 0E` |
| 4/7 | `000357`, page 3 | exact complete `01 0F` |
| 5/7 | `000378`, page 4 | exact complete `01 10` |
| 6/7 | `000401`, page 5 | exact complete `01 11` |
| 7/7 | `000423`, page 6 | exact complete `01 12` |

An additional exact complete `01 13` is mandatory before the final fixed
`01 07 00 01 01 01 02 01 02 13 03 13 04`. The service then uses the observed
17.6 ms command-to-close interval and immediately reopens 38400/8N1,
`Handshake.None`, RTS LOW, DTR HIGH. `LiveActive` is set only after a complete
`FB FB ... FF` frame is assembled.

Unexpected or timed-out replies stop the sequence without later pages, final
`01 07`, reopen, or automatic restoration. Raw TX/RX capture and SQLite
recording remain at the transport boundary.

## Diagnostics

Each write records `START WRITE n/7` or `RESTORE WRITE n/7`, command/page, byte
count, check byte, response, and elapsed time. The raw TX capture row also carries
the write number and mechanical protocol fields; no unknown payload field is
given an invented semantic name.

## STOP operations

The UI exposes two distinct actions:

- **Stop Live** closes the RTS LOW / DTR HIGH live COM port, sends no command,
  enters `NotLive`, and retains the frozen pre-START snapshot.
- **Stop + Restore** first performs the same close if necessary, observes the
  captured approximately 200.3279 ms close-to-cleanup-open interval, opens
  38400/8N1 with RTS LOW / DTR LOW, runs the complete cleanup interrogation,
  transmits the precomputed restoration exchange made from the frozen original
  pages, requires replies through `01 13`, sends the captured final `01 07`,
  waits the observed 4.5618 ms, and closes without reopening.

Fresh cleanup interrogation pages gate responses and are recorded, but never
replace the frozen source used for restoration.
